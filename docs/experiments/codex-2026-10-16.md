# Codex image bridge feasibility / implementation record — 2026-10-16

## Decision

**Official CLI mode: unavailable, NOT implemented.** Codex has an internal image tool, but no verified, documented, non-interactive CLI image-file contract was identified. `codex exec` can omit the image tool, emit text instead of a file, or fall back to local image drawing. A successful `codex login status` is **not** proof of image generation eligibility.

**Experimental mode: implemented as a gated local adapter, NOT live-verified.** WallTrek can spawn a separately installed [jdmnk/codex-imagegen-cli](https://github.com/jdmnk/codex-imagegen-cli) executable. The helper's README as inspected on 2026-10-16 (alpha v0.2.0) documents `generate`, `edit`, `--image`, `--style-image`, `--prompt-file`, `--out`, and PNG output. Its endpoints are undocumented and it reads/refreshes the current user's file-based Codex `auth.json`. Its authors do not promise stability. **WallTrek never opens, reads, copies or logs this credential file.** This adapter does not support account/API-key bypasses, quota rotation or UI cookie extraction.

Evidence:
- Official Codex source: https://github.com/openai/codex/blob/main/codex-rs/ext/image-generation/src/tool.rs
- CLI noninteractive behavior: https://github.com/openai/codex/blob/main/docs/exec.md
- Reported missing image tool on Windows: https://github.com/openai/codex/issues/19133
- Reported image-save failure and fake placeholder: https://github.com/openai/codex/issues/28526
- Helper docs: https://github.com/jdmnk/codex-imagegen-cli/blob/main/README.md

## Included in this PR

- Explicit checkbox consent, default OFF. User may set executable paths or allow PATH resolution. Never scan other Windows users' profiles.
- `codex --version`, `codex login status` and helper version separately inspected with 12-second bounded invocations. Installed/signed-in/helper-present statuses are independent of unknown image eligibility.
- User-initiated test generate and test edit (using a user-provided identity reference path) are separate calls. Test result describes valid PNG bytes/dimensions; visual identity cannot be proven automatically.
- The legacy text-to-image dropdown exposes `Codex (experimental)` only when enabled; no public API key is required. Account quota/cost is **unknown**, not free.
- Dedicated, UI-independent `CodexImageBridge` with up to five reference inputs, maximum one style-only reference, identity-preservation prompt for identity inputs, cancellation, 5-minute operation timeout, no shell interpolation for helper, prompt file, isolated random temp directory, bounded input/output checks and cleanup. The Windows PNG decoder validates final image bytes; no placeholder or assistant-text success is accepted. Existing wallpaper is not replaced if generation fails.
- Typed errors: `NotInstalled`, `NotSignedIn`, `UnsupportedAccount`, `ToolUnavailable`, `RateLimited`, `Timeout`, `InvalidImage`, `BackendChanged`, `Cancelled`.
- Failures never trigger an automatic upload to OpenAI API, Google, or another host.
- Offline fake-runner tests and Windows GitHub Actions configuration. No user credentials/real photos in the repo.

**Known scope limit:** Full reference-library/editor UX is in roadmap milestone 3; the main wallpaper generation form currently uses prompt-only Codex. The adapter's `EditAsync` and Settings edit smoke-test path accept references and are available for later integration. Test images are discarded after validation, not published or stored in history.

## Manual Windows release gate (NOT YET DONE)

1. On a disposable Windows 10/11 user profile, build WallTrek and run `dotnet run --project tests/WallTrek.Codex.Tests/WallTrek.Codex.Tests.csproj` (offline fake tests). Confirm the WinUI app starts, legacy OpenAI/Google still show up, Codex is hidden by default, and switching consent OFF hides it.
2. Install **and audit** the third-party helper yourself using its upstream instructions (Python 3.10+, `uv`, `uv tool install -e .` from a reviewed checkout). Do not have WallTrek download it. Pin/review the exact helper revision and verify version/command semantics.
3. Log in with `codex login` as the same Windows user. `codex login status` must report signed in. Keyring-only sign-ins may be incompatible with this helper; do **not** copy tokens to fix this.
4. In API Settings, check installation/login (no image generated). Opt in after reading the warning. Click **Test real generation**; confirm a genuine PNG and dimensions, not a script-generated fake placeholder.
5. Supply a disposable, consented sample photo path and click **Test real edit**; compare the actual result visually with the input, confirm correct subject identity. Verify one to five inputs and style-only rules via isolated bridge testing. Do not commit personal photos or logs.
6. Test missing CLI, missing helper, incompatible credentials, 401/403, 429, remote endpoint change, denied input, bad/oversized PNG, cancellation/timeout and a refused request. Validate no unintended wallpaper replacement, no raw stderr/stdout, no credential leaks, and temp-directory cleanup.
7. Check the latest ChatGPT/Codex service terms and helper security/license before public distribution. Unofficial endpoints may change without notice.
